Architecture of Reqnroll 


Feature (.feature) → Step definition (.cs) 






Scenario: Title 
Given [Prerequisite] 
When [Actions/Operation] 
Then [Assertion] 




Steps to create a BDD framework in .NET
1. Add extension for ReqnRoll (Extensions → Reqnroll) 
2. Create ReqnRoll project 
3. Add or update the dependencies 
   1. Microsoft.Playwright (.dll) 
4. Create Feature file 
   1. Add Feature header 
   2. Add feature description 
      1. Unformatted description 
      2. Formatted description 
In order to [business goal] 
As a [role] 
I would like to [visible change in the application] 
5. Scenario 
   1. Add title 
   2. Add the steps (minimum one given, when, then) 
6. Create step definition 
7. Step parameterization 
   1. Reuse the code 
   2. To reduce duplicates in the step definition 
8. Scenario outline 
   1. One scenario - multiple sets of test data 
   2. Reduce duplicates in the feature file 
9. Background 
   1. If there are repeated given for all scenarios under a single feature file, then use background; otherwise, avoid it. 




















Important concepts - (Improve the readability/maintenance) 
1. Step parameterization - code reuse 
2. Scenario outline - one scenario - multiple sets of test data 
3. Background - repeated given 
4. Datatable - tabular data
